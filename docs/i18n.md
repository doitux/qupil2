# Languages and theme

How Qupil handles translations and the light/dark colour theme.

## Languages

* **English is the source language.** `qupil_en.qm` is always installed first, so a string that is missing in another language shows in English instead of as a raw ID.
* **German** keeps the wording of Qupil 1.4.1. Only technical leftovers were removed (keyboard `&`, the ` - Qupil` title suffix, HTML, hard line breaks), plus 27 spelling fixes and one factual fix (see below). Every single change is listed in the review workbook (see below), sheet *Deutsch geändert*.
* **French and Spanish** use the formal address (*vous*, *usted*). Musical terms: FR *élève, cours, morceau, audition, formation musicale*; ES *alumno, clase, obra, audición, lenguaje musical*. French gets non-breaking spaces before `: ? ! ;` and inside « » automatically.
* The language setting is `"system"` (default) or `en`/`de`/`fr`/`es`. It is stored per device (`QSettings`, key `ui/language`) and is **not** synced. With `"system"`, the first supported language from the OS preference list wins; anything else falls back to English. Dates and numbers follow the user's region, not the UI language.
* Switching is live: `LanguageManager.language = "fr"` swaps the translators and calls `QQmlEngine::retranslate()`. On desktop a change of the OS language while Qupil runs is picked up as well.

### String IDs

All texts are ID-based (`qsTrId()` in QML, `qtTrId()` in C++). IDs are `area.thing[.detail]`, lower case, dots between levels, underscores inside words:

```
about activity app appearance archive audio backup birthday candidates common db defaults doc
event format import instruments language lesson library menu metronome migration more nav note
notify piece reminder reminders schedule settings student sync today weekday
```

```qml
Label  { text: qsTrId("student.delete.confirm").arg(student.name) }
Label  { text: qsTrId("candidates.ago.months", months) }   // plural: pass the number
Button { text: qsTrId("common.save") }
```

```cpp
QMessageBox::critical(nullptr, qtTrId("db.update_failed"),
                      qtTrId("db.update_failed_detail").arg(from).arg(to).arg(error).arg(u"fhammer@qupil.de"_s));
```

Placeholders are always `%1`, `%2`, … (1.4.1 had a `%0`, which Qt does not know; that entry was renumbered). Plural strings use `%n`; English, German, French and Spanish each have two forms. Every entry with a non-obvious placeholder carries a translator comment.

### Adding or changing strings

`tools/i18n/catalog.py` is the single source of truth. Don't edit the TS files by hand, and don't run the CMake target `update_translations` – lupdate would rewrite them.

```sh
python3 -I tools/i18n/build.py tools/i18n/raw.json i18n         # writes i18n/qupil_*.ts, checks everything
python3 -I tools/i18n/review_xlsx.py tools/i18n/raw.json i18n   # optional: i18n/Qupil2-Uebersetzungen.xlsx for review
```

Commit the changed `catalog.py` together with the regenerated TS files; the *Translations* workflow rejects a pull request where they differ.

`build.py` stops with an error list if an ID is duplicated, a placeholder is missing in one language, a plural entry lacks `%n` or a form, or a 1.4.1 string is neither mapped nor listed in `DROPPED`. New strings (without `old=`) need `de=` as well. `raw.json` is the 1.4.1 German translation as data (`extract.py` recreates it from `ts/qupil_de.ts` of 1.4.1).

To find IDs that are used in the code but missing from the catalog, run lupdate into a scratch file and look for entries without translation: `lupdate src qml -ts /tmp/ids.ts`.


### Adding a language

1. Add the code and native name to `kLanguages` in `src/core/LanguageManager.cpp`.
2. Add a `xx=` value to every entry in `tools/i18n/catalog.py`, and the language to `tools/i18n/build.py` (the `LANGS` table and the language lists in the checks).
3. Add `i18n/qupil_xx.ts` to `QUPIL_TS_FILES` in `CMakeLists.txt` and, for mobile, `xx` to the `qtbase_*.qm` loop.
4. Add `xx` to `CFBundleLocalizations` in `platform/ios/patch-info-plist.sh` and to the `foreach` in `CMakeLists.txt`, add an `xx.lproj/InfoPlist.strings` and add `xx` to `platform/android/res/xml/locales_config.xml`.

## Platform files (not wired into the build yet)

* **iOS / iPadOS:** `platform/ios/patch-info-plist.sh` adds `CFBundleLocalizations`, the per-app language in *Settings › Qupil*, the Bonjour type for Wi-Fi sync and Files app access to the `Info.plist` Qt generates. `platform/ios/<lang>.lproj/InfoPlist.strings` hold the translated permission text for the local network (Wi-Fi sync); pairing uses a typed code, so no camera access is needed.
* **Android:** `platform/android/res/xml/locales_config.xml` for the per-app language (Android 13+), referenced from `<application android:localeConfig="@xml/locales_config">` in `platform/android/AndroidManifest.xml`.
* **Mobile Qt strings:** `CMakeLists.txt` bundles `qtbase_de/fr/es.qm` into `:/i18n` on Android and iOS, where Qt's own translations are not installed.

## Theme (dark mode)

`Theme.qml` is a singleton with colour tokens. Use tokens only, never hex values in components.

```qml
Rectangle { color: Theme.surface; radius: Theme.radius
    Label { text: qsTrId("today.notices"); color: Theme.textMuted }
}
Button { palette.button: Theme.accent; palette.buttonText: Theme.textOnAccent }
```

* `Theme.mode`: `"system"` (default), `"light"` or `"dark"`. Stored per device with QtCore `Settings` (category `appearance`, key `mode`), not synced.
* `"system"` follows `Qt.styleHints.colorScheme` (Qt ≥ 6.5) and changes live when the user switches the OS to dark mode – on iOS, Android, Windows, macOS and the common Linux desktops.
* With Qt ≥ 6.8 a forced `"light"`/`"dark"` also switches native window decorations and dialogs; on 6.5–6.7 only Qupil's own UI switches.
* Dark mode look: deep aubergine black instead of neutral grey, plum lightened (`#A35C88`) so it keeps contrast, lime stays the signal colour for “now”. All text/background pairs of the tokens reach WCAG AA (4.5:1) in both modes, status badges and icon tiles at least 5.3:1.

| Group | Tokens |
|---|---|
| Surfaces | `bg`, `surface`, `surfaceAlt`, `surfaceSunken`, `border`, `divider`, `segment`, `segmentActive` |
| Text | `text`, `textSecondary`, `textMuted`, `icon` |
| Brand | `accent`, `textOnAccent`, `accentText`, `accentSoft`, `hero`, `heroText`, `heroMuted`, `heroButton`, `lime`, `textOnLime` |
| Inverse | `inverse`, `textOnInverse`, `inverseMuted` (active chip, pressed toggle) |
| Mini player | `player`, `textOnPlayer`, `playerMuted` (floating metronome) |
| Feedback | `danger`, `dangerFill`, `textOnDanger`, `neutralFill`, `success`, `successSoft`, `switchOn`, `switchOff`, `overlay`, `shadow` |
| Piece status | `statusBg[state]`, `statusFg[state]` (0 planned, 1 in progress, 2 paused, 3 ready for recital, 4 finished) |
| Icon tiles | `tile.orange/plum/blue/green/yellow/gray` with `.bg` and `.fg` |
| Avatars | `avatar[i % 3]` |
| Shape | `fontFamily` (Figtree), `radiusSmall` 10, `radius` 16, `radiusLarge` 22, `touchTarget` 44 |

**Coloured text in notes.** Notes are rich text and may contain colours chosen in light mode. `Theme.noteColor(c)` returns a lightened version in dark mode (hue and saturation stay, a lightness below 60 % is raised to 75 %). Apply it when rendering stored note HTML, not when saving, so notes look right on every device whatever its mode.

## German: what changed compared to 1.4.1

Full list with old and new text: review workbook, sheet *Deutsch geändert* (124 entries). In short:

* **One factual fix:** the second tuning tone was labelled *H*, but the sound file plays 466 Hz, which is *B* (B♭). German now says *B*.
* **27 spelling fixes**, e.g. *Regelmäig → Regelmäßig*, *Unterrrichtsnotizen → Unterrichtsnotizen*, *imporieren → importieren*, *Programm-Author → Programm-Autor*, *(CVS) → (CSV)*, *wir die → wird die*, verbs after a noun no longer capitalised (*Notiz Löschen → Notiz löschen*), *PDF Datei → PDF-Datei*, *City: → Ort:* (an untranslated leftover).
* **Technical only** (wording unchanged): keyboard shortcuts `&`, ` - Qupil` in dialog titles, HTML markup, hard line breaks, e-mail address and website as placeholders, nine fixed “1 Monat … 24 Monate” entries merged into one plural entry, sentence fragments that were glued together in code turned into one string with a placeholder.

To undo a change, set `de="…"` on that entry in `tools/i18n/catalog.py` and regenerate.

**Not carried over** (32, sheet *Entfernt*): desktop keyboard shortcuts, one-letter column codes, empty menu entries, pre-1.0 database conversion texts, SDL sound-file errors (the metronome now uses Qt Multimedia), and URL-only HTML.
