# Qupil in the Microsoft Store

Qupil for Windows comes in two forms:

| | Setup (`Qupil-Windows-x64-Setup-….exe`) | Microsoft Store (`.msix`) |
|---|---|---|
| Signed | no: Edge and SmartScreen warn | by Microsoft: no warnings, also with Smart App Control |
| Updates | run a newer setup | automatic through the Store |
| Where | nightly release on GitHub | Store listing (Store ID `9MW682SL4MMK`) |
| Data | `%APPDATA%\Qupil`, settings in `HKCU\Software\Qupil` | the same place |

Both use the same data, so you can switch from one to the other. Having both installed works but puts two "Qupil" entries in the Start menu. After installing from the Store, uninstall the setup version under *Settings › Apps*. The data stays where it is.

## The package

- `platform/windows/msix/AppxManifest.xml.in` is the manifest. The identity comes from Partner Center › Qupil › *Product identity*. Never change it: Name `FelixHammer.Qupil`, Publisher `CN=8ECD378F-712C-47D5-879A-61B45647999D`, PublisherDisplayName `Felix Hammer`.
- `platform/windows/msix/Assets/` holds the icons, generated by `tools/icons/make_icons.py`. They include target sizes without a plate, so the taskbar does not show the icon on a coloured square.
- The Desktop workflow builds the package on every run from the same deployed folder as the setup. It adds the MSVC runtime, because a Store package cannot rely on one being installed. The package comes out as the artifact **qupil-windows-store** (`Qupil-Windows-x64-Store-<build>.msix`).
- Version: `major.minor.<run number>.0`, for example 2.0.112.0. Every Store upload needs a higher version than the last one, and the Store wants the last part to be 0.
- The package is not signed. The Store signs it after certification.

### Data outside the package

By default Windows redirects what a packaged desktop app writes to `AppData` and `HKCU` into a private location of the package, and deletes that location when the app is uninstalled. That would delete a teacher's whole database on uninstall. The manifest switches this off (`desktop6:FileSystemWriteVirtualization` and `desktop6:RegistryWriteVirtualization` set to `disabled`), which needs the restricted capability `unvirtualizedResources`.

### Checked in CI

The workflow signs a copy of the package with a throwaway certificate that has the Store's publisher name and is trusted only on the runner. It then:

1. installs the copy;
2. starts it inside the package through the alias `qupil.exe`, running the QML smoke test with a data folder under `%APPDATA%`;
3. checks that the folder was written to the real `%APPDATA%` and not into the package;
4. uninstalls the package and checks that the folder is still there.

## Submitting (Partner Center)

1. Download the artifact **qupil-windows-store** from the run page of the Desktop workflow (*Actions › Desktop › run › Artifacts*) and unzip it.
2. Partner Center › *Apps and games* › **Qupil** › *Start your submission*.
3. **Pricing and availability:** Free. Under *Visibility* you can choose to make the app available only through a direct link, without it showing up in Store search.
4. **Properties:**
   - Category *Education*. Privacy policy URL: the privacy page on qupil.de.
   - Under *Product declarations*, leave everything else at the default.
5. **Age ratings:** fill in the questionnaire. Qupil has no user-to-user communication, no purchases and no ads.
6. **Packages:** upload the `.msix`. Partner Center asks why the restricted capabilities are needed; paste the justification below.
7. **Store listings:** German and English descriptions and screenshots. The screenshots are in `Qupil-Screenshots-nightly-<commit>.zip` on the nightly release (desktop size).
8. *Submit to the Store.* Certification usually takes a few hours up to a few days.

Every later update repeats steps 1, 2 and 6 (upload the new package, keep everything else).

### Justification for the restricted capabilities

> **runFullTrust:** Qupil is a classic desktop application (Qt/C++) packaged with the Desktop Bridge; it needs full trust like every packaged Win32 app.
>
> **unvirtualizedResources:** Qupil keeps its database, backups and settings in `%APPDATA%\Qupil` and `HKCU\Software\Qupil`, the same places as the version that is installed with a setup program and has been in use for years. Teachers switch between both versions and must find their data. Above all, the lesson records of their students must not be deleted when the app is uninstalled or reinstalled, which would happen with virtualised (package-private) storage. Qupil writes only to its own folder and key.
